# AGENTS.md — rasbpi-networking

Pi-hole + monitoring stack (Prometheus, Grafana, Loki, Promtail, Uptime Kuma,
Unbound) deployed on `pi-networking` (192.168.1.5, Raspberry Pi 5).

## Repo topology (IMPORTANT)

This repo exists as two clones that must be kept consistent:

- **Desktop / canonical:** `/home/keverall/repos/rasbpi-networking` (this checkout)
- **Pi deployment clone:** on the Pi's SD card at
  `/home/pi-networking/repos/rasbpi-networking`. When the card is plugged into
  the desktop it mounts read-only at
  `/run/media/keverall/rootfs/home/pi-networking/repos/rasbpi-networking`.

Several subdirectories are **LIVE Docker bind-mount volumes** on the Pi
(`./pi-hole/etc-pihole` → `/etc/pihole`, `./pi-hole/uptime-kuma` → `/app/data`).
Running services (FTL DNS, Uptime Kuma, Unbound) rewrite those files at runtime,
which is why the working tree drifts from `HEAD` even without manual edits.

## Git workflow rules (MUST follow)

1. **Always commit after an update.** After ANY edit to this repo — on the
   desktop checkout OR on the Pi clone — make a git commit with a descriptive
   message before ending the task. Never leave the working tree dirty at the
   end of a session/task.
2. **Keep both clones consistent after a sync.** When syncing the desktop repo
   with the Pi clone, ensure BOTH end up committed at the same content. If you
   commit on the desktop repo and the Pi clone has a local commit, reconcile on
   the Pi with `git pull --rebase` (or `git reset --hard origin/main` after the
   desktop commit is pushed).
3. **Do not commit live runtime artifacts.** The following are generated/maintained
   by running services and must stay out of git (see `.gitignore`):
   - `pi-hole/etc-pihole/pihole.toml` and `pi-hole/etc-pihole/dnsmasq.conf`
     (regenerated by FTL on every start/reload)
   - `pi-hole/etc-pihole/*.db`, `*.db-*`
   - `pi-hole/unbound/unbound.pid`
   - `pi-hole/uptime-kuma/kuma.db`, `kuma.db-shm`, `kuma.db-wal`
   Only commit intended config: compose files, env, dashboards, Prometheus
   rules, docs, and this `AGENTS.md`.
4. **Edit on the canonical repo, then sync.** Prefer making changes in the
   desktop checkout, commit here, then push/sync to the Pi, rather than editing
   the Pi's live volume directly. If you must edit on the Pi, commit there too.
